# SQLite Database Schema: `metadata.db`

Below is the complete database schema of `metadata.db`, which acts as the unified analytics studio control center. This database manages uploaded files, database connection configurations, chat sessions, message histories, semantic metric mappings, and newly migrated application-wide calculation settings.

---

## 📊 Table Specifications

### 1. `files` (Uploaded Local Files)
Stores metadata for CSV and Excel files uploaded locally by users. The actual raw data is processed dynamically via DuckDB.

| Column | Data Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | `TEXT` | `PRIMARY KEY` | Unique identifier (e.g. `file-177983...`) |
| `alias` | `TEXT` | `NOT NULL`, `UNIQUE` | User-defined table name in SQL queries (e.g. `satislar`) |
| `original_name`| `TEXT` | `NOT NULL` | Original filename as uploaded (e.g. `q4_sales_report.xlsx`) |
| `file_path` | `TEXT` | `NOT NULL` | Absolute system filepath on the backend server |
| `row_count` | `INTEGER` | | Total rows detected during initial parse |
| `schema_json` | `TEXT` | | JSON string representing column names and auto-detected datatypes |
| `uploaded_at` | `TIMESTAMP`| `DEFAULT CURRENT_TIMESTAMP` | Date and time the file was uploaded |

---

### 2. `sources` (Remote Data Connections)
Manages connection configurations for external relational databases.

| Column | Data Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | `TEXT` | `PRIMARY KEY` | Unique source identifier |
| `type` | `TEXT` | `NOT NULL` | Database type: `sqlite`, `postgresql`, `mysql`, `mssql` |
| `display_name` | `TEXT` | `NOT NULL` | User-friendly label displayed in navigation panels |
| `connection_details` | `TEXT` | | JSON encrypted/masked object of host, port, db name, user, password |
| `schema_cache` | `TEXT` | | Cached JSON schema structure (tables, columns, types) to accelerate AI query planning |
| `last_schema_update` | `TIMESTAMP` | | Timestamp of the last successful schema cache refresh |
| `labels_json` | `TEXT` | `DEFAULT '[]'` | Discovery and searching tags (e.g. `['production', 'sales']`) |
| `is_active` | `INTEGER` | `DEFAULT 1` | Binary flag (0 = disabled, 1 = enabled) |

---

### 3. `sessions` (Analytical Chat Sessions)
Groups logical threads of analytical queries into independent workspaces.

| Column | Data Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | `TEXT` | `PRIMARY KEY` | Session ID (e.g. `session-177984...`) |
| `title` | `TEXT` | `NOT NULL` | Title of the session, auto-generated from the first query |
| `active_source_id` | `TEXT` | `NOT NULL` | Main active working dataset or database |
| `created_at` | `TIMESTAMP`| `DEFAULT CURRENT_TIMESTAMP` | Session creation timestamp |

---

### 4. `messages` (Conversation & Execution Logs)
Maintains conversation messages, generated execution queries, and results.

| Column | Data Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | `TEXT` | `PRIMARY KEY` | Unique message ID |
| `session_id` | `TEXT` | `NOT NULL`, `FOREIGN KEY` | Reference to parent `sessions(id)` (On Cascade Delete) |
| `role` | `TEXT` | `NOT NULL` | Sender role: `user` (sorgu) or `agent` (cevap) |
| `text` | `TEXT` | | Summary response text or final answer formatted in markdown |
| `status_history`| `TEXT` | | JSON array of thinking steps (status logs) shown in stream |
| `code` | `TEXT` | | SQL or Python code generated by the agent or edited by the user |
| `code_language` | `TEXT` | | Execution language indicator: `sql` or `python` |
| `data_json` | `TEXT` | | JSON string representing the output dataframe (columns, rows, counts) |
| `visualization_json` | `TEXT` | | JSON string representing the Plotly chart layout configurations |
| `auto_corrections_json` | `TEXT` | | JSON string representing table auto-corrections or recommendations |
| `error` | `TEXT` | | Execution error message or trace details |
| `created_at` | `TIMESTAMP`| `DEFAULT CURRENT_TIMESTAMP` | Message creation timestamp |

---

### 5. `semantic_mappings` (Semantic Layer Meta)
Assigns display aliases and business definitions to fields to maximize AI query accuracy.

| Column | Data Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `source_id` | `TEXT` | `PRIMARY KEY` | Unique database source reference |
| `mapping_json` | `TEXT` | `NOT NULL` | JSON string mapping columns to human-readable names and details |

---

### 6. `settings` (Migrated Core Configuration)
Stores application-wide system configurations, newly migrated from local cookies/storage.

| Column | Data Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `key` | `TEXT` | `PRIMARY KEY` | Setting key (`deepseek_key`, `deepseek_url`, `deepseek_model`) |
| `value` | `TEXT` | | Configuration parameter value |
